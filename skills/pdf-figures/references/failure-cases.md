# 失败案例与处置

这份文档只收「真的发生过」的失败，每条都给出**怎么认出来**和**怎么处置**。
来源是 `bench/` 下的实测 run，不是推演。

## 1. 图注口径冲突（最常见）

**现象**：裁出来的图比标注框大一圈，IoU 卡在 0.4–0.5 之间，时好时坏。

**实例**：一页两幅图，Fig 6 的图注横跨整栏。

| | 框 |
|---|---|
| 版面块标注 | `[0.24, 0.44, 0.76, 0.84]`（只含图形） |
| 交付口径 | `[0.07, 0.44, 0.92, 0.93]`（图形 ∪ 图注） |

两者交集等于标注框本身，并集大 2 倍，IoU 掉到 0.5 以下。

**处置**：这不是错误。先确认下游要哪种口径，再决定是否带图注；要两种就导两份。
验收时用「含图注」口径评交付物，用「版面块」口径评定位，别混着看。

## 2. 多面板合并

**现象**：一个框盖住 (a)(b) 两个子图，标注却是两个框。

**判别**：预测数量少于标注数量，但每个预测框都完整覆盖若干标注框。

**处置**：合并通常才是交付物要的。评分器里的 `merged` 口径就是为这种情况准备的；
只有用户明确要单面板时才用 `split` 拆。

## 3. 页眉被卷进来

**现象**：裁图的顶部多出一条半截文字。

**原因**：墨迹收缩是忠实的，它只说「这里有东西」。页眉在上方，且与图之间通常有气隙。

**处置**：上边界用语义判断，或遵守「顶部 7% 页眉带」的默认排除。收缩只能收紧，
不能替你去噪。

## 4. 暗底页阈值崩塌

**现象**：整页被当成墨迹，收缩框等于整页。

**原因**：阈值默认「背景 − 18」，背景是 41 的暗色页上这等于把所有东西都算成墨迹。

**处置**：`pdfx` 已内置反相（背景众数 < 128 时先反相）。自己写脚本时要记得这条。

## 5. 扫描噪声导致整页判墨

**现象**：干净页正常，扫描页框变成整页。

**实测**：固定阈值 245 时，扫描页直接崩成 `(0,0,1,1)`；相对阈值（背景−18，落在 196–236）
则稳定。所以**不要**把阈值写成常数。

## 6. 裁出来是空白

**现象**：`crop` 输出的图全白。

**原因**：渲染库的裁剪参数顺序写反（pypdfium2 是 left/bottom/right/top）。
竖排两个方向相反，非常容易写反，而且不报错。

**处置**：`selftest` 里有专门的用例；改渲染层后必须跑。

## 7. 评测泄漏（不是取图问题，但会毁掉结论）

**现象**：某次跑出 F1=1.000、mIoU=1.000，耗时还异常低。

**原因**：输入文件名带着数据集 id，而 GT 就放在同一块磁盘上，Agent 可以直接读。

**处置**：输入必须复制成不透明文件名并放在隔离目录（`bench/stage.py`），映射表放在输入目录之外。
**凡是让 Agent 直接接触文件系统的评测，都要先假设它会去翻答案。**
