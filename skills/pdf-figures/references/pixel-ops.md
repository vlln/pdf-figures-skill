# 像素算子：为什么这么设计

这份文档回答「为什么阈值、投影、行条要这样做」，避免后来者把它们当随意参数改掉。
所有数字来自实测（OmniDocBench 学术子集，见仓库 bench/）。

## 墨迹阈值必须是相对的

`painter` 的传统做法是「小于 245 算墨」。在干净矢量页上它工作正常；在带噪点的扫描页上，
噪声像素会遍布全页，阈值 245 把整页判成墨迹，收缩结果直接退化成整页。

实测（同一页，加 0.6° 旋转 + 逐像素噪声 + JPEG q72）：

| 阈值 | 得到的包围盒 |
|---|---|
| 干净页 245 | (0.094, 0.038, 0.906, 0.964) |
| 扫描页 245 | (0.000, 0.000, 1.000, 1.000) ← 崩 |
| 扫描页 230 / 210 / 190 | (0.092, 0.035, 0.911, 0.967) ← 稳定 |

所以阈值取「背景众数 − 18」，并夹在 [150, 245]。扫描件的背景不会是 255，
这一步自动跟着背景走，不需要用户传参。

## 暗底页面先反相

背景众数 < 128 的页面（照片、反色扫描）必须先把图像反相再算墨迹，否则「背景 − 18」
是一个毫无意义的数。反相后背景回到 200+，阈值逻辑原样可用。

## 投影用一维缩放，不用逐像素循环

行/列投影只需要「每行有多少墨」，Pillow 的 `resize((1, H), Image.BOX)` 就是列平均，
一次调用完成，比手写双重循环快两个数量级，也不需要 numpy。

## 行条（strip）为什么比坐标可靠

模型看图后给 y 坐标，误差常在图注行高以上。但它**数得清有几行**。
把边界区域按行切开、画上编号，模型只需回答「切到第 N 行」，脚本把行号换算成精确 y。
实测同一处边界：直接给坐标偏 3.4%（切掉两行图注），走行条误差为 0。

这是整套方法里最值钱的一条：**连续量换成离散选择**。

## 触边检测是免费的验收信号

收缩之后如果墨迹贴着裁剪框的边，说明**你给的框本身切了内容**，不是收缩出了问题。
这个布尔量让「裁得对不对」从主观判断变成可自动检查的断言。实测中它抓出过两次
目测偏紧的框。

注意：外扩过大的粗框本来就会触边（周围有别的文字），触边只对「预期隔离」的框有诊断意义。

## 面板切分靠空白带

行投影里连续为空的区间 ≥ 3% 页高，就是面板之间的气隙。列同理（阈值 6% 页宽）。
这能自动给出面板网格，不需要模型判断——但「拆不拆」仍由模型或用户决定。

## 退化不影响收缩

把同一批页面加旋转、噪声、模糊、JPEG q55 之后，收缩框与干净页收缩框的 IoU 是 **0.985**。
也就是说，扫描件的精度损失几乎全在「没有矢量可重画」，而不在定位。
