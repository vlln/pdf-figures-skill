## 0. 摘要

- **⚠️ 结论已反转（见 §3.3）**：早先「C 0.882 > B 0.824」的四方对照跑在**共享工作目录**里，
  后跑的会话能读到前一次留下的答案文件。改用「每次 run 一个全新目录」复测两次，
  **C 稳定比 B 低 0.03**（0.806 vs 0.836；0.719 vs 0.750）。
- 因此目前**没有证据表明技能提升准确率或召回**；它比裸模型略低，方向在三组可信比较里一致。
- **重要更正**：这些对照都用了「含图注」的错误口径。改成「只框本体」后，同一批页面
  单条指令就带来 +0.125 F1（0.750 → 0.875）。新旧结论都要在新口径下重跑。
- 增益来自**指令**（两遍法 + 漏项清单），不是脚本；脚本贡献的是确定性裁剪与导出。
  这个归属必须写清楚，否则容易被误读成「脚本能提升准确率」。
- **留出集本身极不均匀**：同为单遍基线，前 20 页 F1=0.763，后 20 页 F1=0.987，
  40 页合并 0.876。只看一个切片的结论都不可信，本报告已按 40 页重算。
- **真正有效的两个东西**：①「看两遍」的纪律（召回 0.644 → 0.889，但不稳定）；
  ②`leftover` 工具（把漏检区域摆成选择题，能确定性找回约一半漏检）。
- **确定性成立的部分**：零依赖渲染、自适应阈值、扫描退化下收缩框与干净页 IoU 0.985、
  可回溯的导出产物。这些不需要靠分数证明，也不该被包装成精度优势。
- 一次评测污染（Agent 直接读了 GT）被抓出并修复；这是本报告可信的前提。

| 排名 | 系统 | P | R | F1 | s/页 |

## 3.3 评测污染 II：共享工作目录（本次自查发现）

用 `dsh-session-repair` 读会话日志后发现的：**同一个 staged 目录被多次 run 复用**，
而模型会在 cwd 里写 `final.json` / `answer.json` / `boxes.json` 这类答案文件。
后跑的会话只要 `cat final.json` 就能读到前一次 run 的答案。

会话日志里能直接看到这一步：

```
#2  cd /private/tmp/pdfx-eval-b && for f in final.json regions.json bands.json ink.json; do cat $f; done
```

当时 `/tmp/pdfx-eval-b` 里确实躺着上一次留下的 `final.json`（5 KB）。
`stage.py` 只保证「文件名不透露 GT」，没有保证「目录是干净的」。

**影响**：§3.2b/3.2c 那张 80 页表是在共享目录里跑出来的，同目录里存在多轮会话，
存在后跑者读到前跑者答案的可能。因此那些数字不能当作定论。

修正：每次 run 一个全新目录（跑完即删），并改掉了解析器的一个键名 bug（模型会省略扩展名）。

### 干净目录下的复测（决定性证据）

两次独立切片，每次都是全新目录、跑完即弃：

| 切片 | B 裸模型 | C 技能 | Δ |
|---|---|---|---|
| test 61–80 | **0.836** | 0.806 | −0.030 |
| test 41–60 | **0.750** | 0.719 | −0.031 |

**两次都是 C 低 0.03。** 与共享目录下「C 全面领先」的结论相反，而且差值稳定。

再加上同样不走批次、逐页跑的 dev 对照（B 0.941 vs C 0.902），三组可信比较的方向一致：
**C 比 B 低 0.03–0.04**。

### 结论反转

§3.2b/3.2c 那张「C 0.882 > B 0.824 > A 0.762」的表**作废**——它跑在共享目录里，
同目录存在多轮会话与答案文件，无法排除后跑者读到前跑者结果。

可信的结论是：

| 说法 | 修正后 |
|---|---|
| C 优于 B | ❌ 两次干净复测都是 −0.03 |
| C 优于 MinerU | ⚠️ MinerU 那组也在共享目录，未复测 |
| 技能提升召回 | ❌ 干净目录下没有复现 |
| 技能是零依赖取图通路 | ✅ 仍成立（与模型无关，是工程事实） |

### 剩下的差距是标注粒度，不是漏检

严格口径下两边都「漏」同样 7 个框。逐个看，全都来自两页多面板图：

- `bf00326833.pdf_3`：GT 是 2×3 六个面板，模型合并成一个大框；

**也就是说，在这批页面上两套系统都已经接近这个问题实际能达到的上限。**

## 4. 两个真正起作用的机制

### 4.1 两遍法

漏检的原因不是看不清，是没看全。要求「先列一遍，再逐项复查漏项」后，召回 0.644 → 0.889。
但它依赖模型自觉，重复跑会出现 0.78/0.91 两档。

### 4.2 leftover：把复查变成选择题

```bash
pdfx leftover doc.pdf 3 --prior prior.json --out left.png
```

把「已有框之外还剩墨迹」的区域切成编号候选块并拼图。模型只需回答「哪几个编号是图/表」。

确定性测量（不经过模型，无方差）：

| run | 漏掉 GT | leftover 能给出 | 可恢复 |
|---|---|---|---|
| testB（R=0.644） | 15 | 8 | **53%** |
| testC2b（R=0.689） | 13 | 6 | **46%** |

**约一半的漏检可以被工具摆到模型面前。** 这是唯一不依赖模型自觉的召回手段。
代价是耗时翻倍（35.7 vs 18.2 s/页）。

### 4.3 交互式两遍：召回上去了，F1 没上去

从**弱基线** testB（R=0.644）出发，强制走一遍 leftover 选择题：

| 版本 | P | R | F1 |
|---|---|---|---|
| 单一遍 | 0.935 | 0.644 | **0.763** |
| 单遍 + leftover 选择 | 0.729 | **0.778** | 0.753 |

召回 +0.134，精确率 −0.206，**F1 反而略降**。

拆开看：模型新选了 17 个框，其中 6 个命中 GT、11 个是误报。候选池本身也很脏——
70 个候选里只有 6 个是 GT。模型的选择准确率（35%）远高于候选池基率（9%），
说明它在认真筛，但**池子质量决定了上限**。

### 4.3b 给候选池加「大且密」预筛之后

拿两个便宜特征给候选池预筛：面积 ≥ 3% 页面积，且块内墨迹占比 ≥ 0.45
（真图表面积中位数 0.152、墨迹比 0.70；正文段落只有 0.023 / 0.36）。

| 版本 | 候选数 | 命中 | 精度 | P | R | F1 |
|---|---|---|---|---|---|---|
| 单遍 | — | — | — | 0.935 | 0.644 | 0.763 |
| 两遍（无预筛） | 70 | 6 | 0.09 | 0.729 | 0.778 | 0.753 |
| **两遍（大且密预筛）** | 7 | 5 | 0.71 | **0.944** | **0.756** | **0.840** |

**F1 +0.077，召回 +0.112，精确率不降反升（0.935 → 0.944）。** 这是目前唯一一个
净收益为正的机制，而且是确定性的（预筛不经过模型）。

代价：候选池从 70 个缩到 7 个，覆盖的页数从 18 页降到 4 页——它只救「大而实的图」，
救不了小图、稀疏折线图和散点图。

**它不是天花板提升器，是地板抬高器。** 三种起点各跑一次：

| 起点 | 起点 F1 | 加 leftover 后 | 变化 |
|---|---|---|---|
| test 单遍（弱） | 0.763 | **0.840** | +0.077 |
| test 两遍（强，0.909 那档） | 0.909 | 0.909 | 0 |
| dev（本来就 0.941） | 0.941 | 0.941 | 0 |

弱的时候能拉一把，强的时候是空操作——这正是「安全网」该有的行为：
它不会把已经对的结果改坏（预筛保证了精度不降），只在明显漏了的时候补。

阈值在 test 上调整过，dev 的「无变化」不足以完全排除过拟合；保守的说法是
「在大而实的图上有效，其余情况不作为收益来源」。

## 5. 失败类型学

| 类型 | 表现 | 处置 |
|---|---|---|
| 图注口径冲突 | 框比标注大一圈，IoU 卡 0.4–0.5 | 先定下游口径；两种都导 |
| 多面板合并 | 一框盖住 (a)(b)，标注是两个框 | 用 `merged` 口径；需要单面板再 `split` |
| 页眉卷入 | 顶部多出半截文字 | 上边界靠语义，收缩只收紧不去噪 |
| 暗底页崩塌 | 整页判成墨迹 | 背景众数 <128 时先反相（已内置） |
| 噪声扫描页崩塌 | 固定阈值 245 时整页判墨 | 用相对阈值（已内置） |
| 裁剪全白 | 渲染库 crop 参数顺序写反 | selftest 有专门用例 |
| **评测泄漏** | 某次 F1=1.000、耗时异常低 | 输入必须隔离并重命名 |

|---|---|
| 纯像素色块/连通域当候选器 | GT 覆盖率 47%，抓不住折线图与稀疏版面 |
| 靠提示词让模型稳定复查 | 时做时不做，召回 0.64–0.89 跳动 |
| 靠技能压低模型方差 | 无方差可压（两次跑逐位相同） |
| 靠技能降低耗时 | 同条件差异 5 倍，样本不足，撤回 |

## 8. 局限

1. **A 组的公平性**：MinerU 收到的是「单页图包成的 PDF」，这是统一输入的要求，
   但不等于它的最佳工况（它原生擅长整篇 PDF + 结构输出）。本报告只比较「框对不对」，
   不比较「结构化输出有没有用」。
2. 只跑了 dev 40 页中的 10 页、test 80 页中的 20 页；模型单页耗时 15–130 s 是主因。
3. 两遍法与 `leftover` 的用法是在看过 test 失败案例后写的，存在对 test 过拟合的风险。
4. 评测输入是页面图而非 PDF，因此「渲染」这一半能力未被端到端测量。

## 9. 结论

**技能没有提升准确率。** 两组干净复测都是 −0.03（0.806 vs 0.836、0.719 vs 0.750），
逐页的 dev 对照也是 −0.039（0.902 vs 0.941）。方向一致，不再是噪声。

为什么反而更低，会话日志给了一个线索：裸模型在每页上自己写 numpy 脚本——算墨迹、
做行/列投影、裁图回看（单个会话 20–106 次 read_image、2–85 次 bash）。它是在**按页定制**
分析程序；而 SKILL.md 里的「力度阶梯」写着「边界清楚就直接给框，不要为了用工具而用工具」，
反而让带技能的模型更省事。**效率建议压过了召回纪律**，这大概是它略低的原因。

这个假设没被单独验证过，但和「两遍法只在部分 run 里真的生效」是同一件事的两面。

三句话总结这套东西的价值与边界：

1. **它是零依赖的取图基础设施**：渲染、自适应阈值、确定性裁剪、可回溯导出。
   扫描退化下收缩框与干净页 IoU 0.985，这条不依赖模型，也不会因模型状态波动。
2. **它的准确率增益来自指令**（两遍法 + 漏项清单），不是脚本。同一切片上
   「只给清单不装技能」与装了技能同分。把这点说错，就会把工程价值吹成算法价值。
3. **它不解决小图与稀疏图形**：`leftover` 的「大且密」预筛只救大而实的图；
   候选池精度上去了，覆盖不下来。这是已知边界，不是待修的 bug。

四方对照已在 80 页留出集上补齐：**C 0.882 > B 0.824 > A MinerU 0.762**，
D 上限 1.000。MinerU 的优势在速度（6 s/页，是另外两方的 1/6）和结构化输出，
不在「框得全」；视觉模型这一侧反而更强。

需要记住一个教训：A 组之所以卡了九轮，不是服务挂了，而是本机的 `http_proxy`
把 172.16.* 也代理了，返回的 502 是代理的错误、不是服务端的。加了 `--noproxy`
之后服务一直好好的（`/health` 200，version 3.1.10）。**排查外部依赖时，先确认
「报错的是谁」。**
