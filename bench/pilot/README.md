# 小样本对照实验（5 次）

> 哪些 run 能用、哪些作废、每条结论有多强：见 [EVIDENCE.md](EVIDENCE.md)。
> 本文件是过程日志，EVIDENCE.md 是结论分级，以 EVIDENCE.md 为准。

目的：比较三种基础配置，再在胜出者上分别测「复审」与「拼图」。

| # | 命令（在仓库根目录） | 问题 |
|---|---|---|
| 1 | `run.py --arm minimal --name e1-minimal` | 原始 Agent 基线 |
| 2 | `run.py --arm ruler --name e2-ruler` | 尺子技能：分数不降、成本更低？ |
| 3 | `run.py --arm pixels --name e3-pixels` | 像素技能：与 2 相比如何？ |
| 4 | `run.py --arm <胜者> --review --name e4-review` | 复审能否提分，代价多少？ |
| 5 | `run.py --arm <胜者> --mosaic 4 --name e5-mosaic` | 拼图能否降成本，掉分多少？ |

解释器统一用 `~/.local/share/pdfx-pilot/env/bin/python`（pypdfium2 5.14.0、Pillow 13.0.0、
numpy 2.5.4），Agent 会话的 PATH 也前置这个环境，三组拿到的 Python 完全一样。
环境放在仓库外：放在仓库里时，PATH 会把仓库位置暴露给 Agent（见下文「第一次 e1 作废」）。

**胜者规则**（1–3 跑完后定，跑之前写死）：F1 差 > 0.05 取高分者；否则取每页耗时低者。
超时、无有效答案按空预测计分，不剔除。

**页面键放宽**：模型偶尔把第 1 页写成 `"1"` 而不是 `"A"`。这是答题格式、不是定位能力，
按位置接受，但记一条 `numeric_label` 问题留痕。提示词不改。旧 run 用
`rescore.py` 重算即可，不必重跑（见下）。

## 1–3 的三组对比

结论与下面「最终结果」一致：三组同分、逐框几乎逐位相同（同页中位 IoU 0.98–1.00）。
一个中间插曲值得记：**放宽页面键之前**，严格分数是 0.821 / 0.686 / 0.821——差别全部来自
「格式错落在几框的页上」：e1、e3 错在 book-tab（1 个框），e2 错在 mag-multi（5 个框）。
同一个笔误，扣分差 5 倍；这差点被读成「尺子技能更差」。

### e5c：命令面从 6 条收到 2 条

把 page/zoom/boxes/check/pack 合并成一条 `view`（取图/刻度/画框/打包四个开关）+ `norm`，
所有几何参数支持 `页号:` 前缀。同一批八页：

| | e2b（六命令） | e5b（六命令+pack） | **e5c（两命令）** |
|---|---|---|---|
| ruler 调用 | 68 | 63 | **58** |
| 步/页 | 27.8 | 29.8 | **25.9** |
| 秒/页 | 90.4 | 114.2 | 92.8 |
| token/页 | 540k | 666k | 555k |
| 合并 F1 | 1.000 | 1.000 | 1.000 |

**它把 e5b 的退步补了回来**（114.2→92.8 秒/页），调用数和步数是六个变体里最低的；
但墙钟与 e2b 持平（+3%，在噪声内），token 略高。

组合确实发生了：38 次取块里 **32 次同一条命令里带了 `--ruler`**，说明开关式被用起来了。

两个没被用的：`--pack` 只用了 1 次（e5b 是 4 次），`--fit union` 一次没用。
可能是 SKILL.md 里那句「目标还没找到时不要用」把打包压得太狠了。

逐页看，收益集中在难页：acad-multi 222→155 秒、mag-multi 109→91 秒；
代价在最容易那页：acad-fig 68→124 秒。单跑一次，逐页波动 30–222 秒，谨慎解读。


### e5 作废：它测的不是「并行」

e5 是 harness 把 4 个整页贴成一张 3486×5039 的大图，给一个共享坐标系。两处错：

1. **这不是并行，是把四个任务塞进一次调用**——模型拿到大图第一件事就是把 A/B/C/D 逐页裁回来
   （轨迹里生成了 A.png…D.png 和 6 张放大图），等于把我的拼图当场拆了。
2. **共享坐标系有害无益**：大图被附件规范化压到 1703×2462，**每页只剩一半像素**，
   模型不得不重裁以恢复清晰度。token +22% 就是这么来的。

### e5b：`pack` 被采用了，但没有省

按正确设计重做：技能只**建议**「多个独立目标可以打包成一张图」，由 Agent 决定；`pack` 把
k 个目标区裁出来并排，**每块各有自己的 0,0 坐标系**，`norm --map` 负责换算。

| | e2b（无 pack） | e5b（有 pack） |
|---|---|---|
| `zoom` 次数 | 39 | **25（−36%）** |
| `pack` 次数 | — | 4（共打了 3+2+4+5=14 个目标区） |
| 看图次数 | 53 | 49 |
| 秒/页 | 90.4 | **114.2（+26%）** |
| 步/页 | 27.8 | 29.8 |
| token/页 | 540k | 666k |

**机制生效了，收益没出现。** `zoom` 确实少了三分之一，14 个目标区被合并进 4 次调用；
但看图总次数只从 53 降到 49——省下来的额度又被别的方式看掉了。
另外多出 `map` 与 `norm --map` 的簿记，bash 调用 160→189。

逐页看，只有最难那页变快（acad-multi 222→178 秒），其余七页全部变慢。
单跑一次、逐页波动 30–222 秒，这个 +26% 大于之前 e2b vs e2 的 12%，但方向明确。

**结论：在这批题上，调用摊销没有兑现。** 它压的是 `zoom` 这一类调用，
而总调用和总时间由别的东西决定——模型看到更便宜的看法，就会看得更多。

### 严格分 0.850 是口径造成的，不是能力差异

严格口径下 18 个预测框 vs 22 个 GT 块，差的 4 个**全部是同一类**：GT 把一幅图的
面板标成多个块，模型按提示词「多面板给一个外框」合成一个框。

| 页 | GT 块 | 预测框 | 情况 |
|---|---|---|---|
| 学术·图表混排 | 5 | 2 | 2×2 四个面板合成 1 个外框 |
| 学术·多目标 | 4 | 3 | 上下叠放的两块合成 1 个 |

换成合并口径（与提示词一致：一幅图 = 一个外框），六组全部 **22/22，零误报**。

这说明**这批题对三种配置都太容易了**，它测不出方法差异——不是方法之间真的相同。
要分开差距，需要选更容易漏检的页（小图、稀疏折线、密集表格），而不是继续加配置。

### 两个公共因素的实际效果

- **复审**：分数不变，时间 +6%、读图 +30%。基线本来就在核对（e2b 用了 6 次 `check`），
  没有可修的东西。它也没找回那两处合并——因为那本来就不是错。
- **拼图（4 页一张）**：**时间 −26%、步数 −43%**，是六组里最省交互的；但 **token +22%**，
  因为一张四联图有 4 倍像素，每次看图的成本也涨 4 倍。省钱取决于按什么计价：
  按交互次数或墙钟算，它赢；按 token 算，它输。

## 换模型：能力差距远大于技能差距

同一套题、同一个 `minimal` 配置（无技能），只换模型。装配层在 `bench/pilot/models/`，
用 `run.py --extra-patch <file>` 追加。

| 实验 | 模型 | 严格 F1 | 合并 F1 | 秒/页 | 步/页 | token/页 | 超时 |
|---|---|---|---|---|---|---|---|
| e1 minimal（3 次中位数） | deepseek-flash | 0.850 | 1.000 | 99.4 | 21.8 | 482k | 0 |
| m2 minimal | **kimi-k2.6**（flowhub） | **0.421** | 0.421 | 666.8 | 57.6 | 3.36M | **4/8** |

**主导差异是速度，不是定位。** 四页撞满 900 秒超时；跑完的四页 F1 **0.593**、
mIoU **0.959**、召回 0.727——框本身是准的，只是慢到交不出来。

定位上的毛病只有两处：

- **框碎**（acad-fig，1 页）：GT 一个框，它给了 6 个——把摘要文字块当图形，又把流程图里的
  结构式、箭头、产率逐个框出来。其余三页都命中（book-tab 0.95、mag-multi 0.96–0.996）。
- **合成图欠框**（mag-fig，4 个目标里 2 个）：照片类框得准（0.96/0.84），三视图那两幅只圈了
  中间一幅（0.43/0.50），没有把上下两个视图一起包进来。

超时页跑了 72–98 步，最后十几次是同一段 numpy 投影脚本反复执行，没有收敛。

### 页面键 "0" 的解析修正（影响 5/22 个 GT 块）

mag-multi 那页答得几乎完美（5 个框 IoU 0.961–0.996），但它把页面键写成 `"0"` 而不是 `"A"`，
解析器当时只认 1 起编号，整页作废——F1 从 0.421 掉到 0.182，全因格式。已在 `parse_answer`
补上「单页时接受 0 起编号」，与既有的 `"1"→"A"` 同一性质（只放宽页面键，不猜单位、不改坐标）。
重算后 deepseek 各轮不变（0.850 / 1.000），kimi 0.182→0.421。

### glm-5.3 不可用（作废）

flowhub 上 `glm-5.3` / `glm-5.2` 只支持文本模态，带图请求直接 400
（`The current model only supports text modality`）；`glm-5` 不报错但静默忽略图片；
`glm-4.6v` / `glm-4.7` 无权限。这次运行改名 `m1-glm53-INVALID-textonly`，不计入结果。

换模型时要动两处：model entry 加 `compat: {supportsDeveloperRole: false}`
（网关只认 system/assistant/user/tool），以及模型不支持时不能写 `reasoningEffort`。

## 看完轨迹后的三处改动（1–3 跑完之后）

**1. 尺子加了「猜-看-改」两个命令。** 轨迹显示模型在**所有组**都会自己写两类代码：
把框画回图上核对（e1/e2/e3 = 8/5/5 次）、以及手写像素测量（56/38/40 次）。
这两件事是它自发要做的，不是多余动作，但每组都要重写一遍。现在合并成一条命令：

```bash
ruler.py boxes <input> --boxes "x0,y0,x1,y1;..." --out b.png   # 裁到并集、放大、每个框带 #n
ruler.py check <input> --boxes "..." --ruler --out c.png       # 整页画框，提交前核对
```

`boxes` 是给模型一次给 n 个猜测框，图里直接能看到每条边差多少，读刻度改数即可。
判断「哪块是图」「这几条线哪条是表框」仍然留给模型——技能只接手**确定性**的那部分
（裁剪、放大、画框、坐标换算）。

改完之后重跑尺子组（e2b），步数几乎不变，但**手写画框从 5 次降到 0 次、手写 numpy
测量从 58 次降到 36 次**，时间 103→90 秒/页、token 629k→540k。


**2. 所有组禁用联网工具**（`tool-web`）。e2、e3 曾在最难那页用 `web_search` 去找原论文的图，
那不属于取图能力。已在 runner 的 patch 里关掉，任何组都拿不到 `web_search` / `web_fetch`。

**3. 尺子技能因此变了版本。** e2 的 0.850 对应改动前的技能；要让 e4/e5 与它可比，
要么重跑一次尺子组（e2b），要么把 e4/e5 建在 minimal 上。见文末「待定」。

## 每次运行做什么

- 每个会话一个新 `/tmp` 目录，只有 `input.pdf`。页面图以原 JPEG 字节嵌入 PDF（不重编码），
  按 200 dpi 定页面尺寸；渲染回来与原图相差 ≤1 px（运行时逐页校验）。
- 提示词由 `prompts/` 拼装：同一任务定义；技能组多一句「已安装技能 X」；
  `--review` 加复审要求；`--mosaic` 说明各页在大页面上的位置。
- `DSH_AGENTS_HOME` 每会话独立，只装本组技能；`~/.agents` 的全局技能与 AGENTS.md 对所有组都不可见。
- 指标来自 `dsh headless --json` 事件流：步数、各工具调用次数、token、墙钟；
  模型名从会话日志读出（当前默认 `deepseek-official/deepseek-flash`）。
- 答案严格解析：坐标超出 0..1 记为 `out_of_range` 问题并照实计分，不做单位修正。

产物在 `.work/pilot/<name>/`：`summary.json`（总表）、`score.json`、`pred.jsonl`、
`sessions/sNN/{prompt.txt,events.jsonl,session.json}`。

## 隔离

每个会话在 `~/.local/share/pdfx-pilot/runs/r-<随机>/` 下运行，并套一层 macOS Seatbelt
（`sandbox-exec`）：

- 只允许读写本会话目录；`~/References`、`~/Projects`、`~/.agents`、`~/.dsh/sessions`、
  `~/.dsh/attachments`、`/tmp`、系统临时目录、其他会话目录一律不可读不可写。
- 会话日志、图片附件、`TMPDIR` 都改到本会话目录里（`--patch` + 环境变量）。
- DSH 自带的 bash 沙箱无法嵌套在 Seatbelt 里，所以设为 `danger-full-access`，由外层统一限制。
- 运行后统计被拦下的工具结果数（`sandbox_denials`），并扫描工具调用里的评测路径（`leak_suspect`）。

## 已知局限
- 评分只用 `graphic_only` 口径（与任务定义一致）。`merged_f1` 允许一个框覆盖多面板 GT。
- 每个条件只跑一遍。逐页耗时在 32–218 秒之间波动，**单次总计的 6% 差异说明不了问题**；
  F1 相差 0.05 以内应视为打平。
- 沙箱只管文件，不管网络；现在联网工具已整体禁用。

## 待定：e4 / e5 用哪个基础配置

1–3 是同分，规则名义胜者是 e2（尺子，103 秒/页），但差异在噪声内。而尺子技能刚改过版本，
所以有两条路：

**清理纪律**：`~/.local/share/pdfx-pilot/runs/r-*` 存着每个会话的沙箱目录和 dsh 会话日志，
**不要 `rm -rf` 它**。2026-11-05 我为了让查看器干净重建，误删了 e1/e2/e3 的 24 个目录，
那三组的 dsh 会话日志就此丢失；`events.jsonl` 仍在，所以分析和 HTML 复盘不受影响，
但它们在 dsh web 里打不开了。`make_view_home.py --force` 会覆盖旧 home，重建前先确认。

`events_to_session.py` 试图把 `events.jsonl` 还原成 dsh 会话格式，**没有成功**：
那个格式是每行一个 zstd 帧，且有未公开的 producer 校验。要看过程请用 HTML 轨迹。

查看实例里每个会话是一个工作区，标题形如 `E2 尺子技能 · acad-fig`；工作目录就是当时的
沙箱目录，能看到 `input.pdf` 和 Agent 自己写的文件。
`dsh-our-free-model` 插件在新 home 里解析不到（与本机 web profile 的软链有关），
只影响「新建回合时选那个模型」，不影响翻看已有会话。
