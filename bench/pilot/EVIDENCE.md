# 证据分级：哪些数字能用，哪些不能

写于 2026-11-06。目的不是重述结论，而是把「哪条结论建立在干净对照上」标清楚。
凡是不能用的一律给原因；原因分四类：**泄漏**（agent 读到答案）、
**污染**（联网拿到原论文）、**设计错**（测的不是想测的东西）、**前置不足**（没调模型）。

## 一、不能用的 run

| run | 原因 | 性质 |
|---|---|---|
| `e1-minimal-INVALID-leak` | PATH 暴露仓库路径，agent 直接读了 `gt_graphic_only.json` | 泄漏 |
| `e2-ruler` | `web_search` 1 次，搜原论文（Pernak 2007） | 污染；且是旧版技能 |
| `e3-pixels` | `web_search` 4 次 + `web_fetch` 抓到 PMC 的原论文图页（F1） | 污染，命中在**最难那页** |
| `e5-mosaic`（k=4） | harness 把四页拼成一张图，分辨率除以 4，模型拿到第一件事就是拆回去 | 设计错 |
| `dry-*`（4 个） | 只构造输入与提示词，不调用模型 | 前置不足 |
| `oracle-k1` / `oracle-k4` | 用 GT 喂进链路，期望 F1=1，是管线自检 | 不是对照 |
| `tooltest` | 工具冒烟 | 不是对照 |
| `m1-glm53-INVALID-textonly` | glm-5.3 是纯文本模型，带图请求 400 | 模型不具备能力 |

## 二、能用的对照（deepseek-flash，单目标，无联网调用）

| run | 配置 | 严格 F1 | 合并 F1 | 秒/页 | 备注 |
|---|---|---|---|---|---|
| `e1-minimal` ×3 | 无技能，跑三次 | 0.850 | 1.000 | **99.4**（86.4–109.3） | 0 次联网调用 |
| `e2b-ruler` | 尺子（改版） | 0.850 | 1.000 | 90.4 | 联网已关 |
| `e4-review` | 尺子＋复审 | 0.850 | 1.000 | 95.7 | 与 e2b 的框逐像素重合 |
| `e5b-pack` | 尺子＋pack（六命令） | 0.850 | 1.000 | 114.2 | pack 0 次 |
| `e5c-view` | 尺子（两命令） | 0.850 | 1.000 | 92.8 | pack 1 次 |
| `e5d-view` | 尺子＋可操作 pack 描述 | 0.850 | 1.000 | 132.2 | pack 4 次 |
| `e5d-r2` | 同 e5d 复跑 | 0.850 | 1.000 | 100.2 | pack 3 次；**同配置方差 32%** |
| `e3b-pixels` | 像素技能（干净重跑） | 0.850 | 1.000 | 93.3 | 22.0 步/页、473k token |
| `p1-prod` ×3 | **生产版技能**，跑三次 | 0.850 | 1.000 | **79.0**（76.1–81.4） | **18.6 步/页**（16.5–18.8）、**309k token**（274–339k） |
| `m2-kimi26-minimal` | 无技能，kimi-k2.6 | 0.421 | 0.421 | 666.8 | 4/8 超时；完成页 F1 0.593 |

`e3-pixels`（联网版）不在表里，见第一节；它被 `e3b-pixels` 取代。

`e5d` 与 `e5d-r2` 是同一个配置，时间差 32%、token 差 56%；而 `p1` 三次只差 7%。
**波动不是常数，取决于行为是否被约束**——所以本文件只在「同条件 3 次、区间不重叠」时下结论。

## 三、结论与强度

| 结论 | 依据 | 强度 |
|---|---|---|
| 这批题上质量已饱和 | 所有 deepseek 臂合并口径 22/22 | 强 |
| 复审不改变结果 | e4 与 e2b 的框逐像素重合（IoU 0.98–1.00） | 强 |
| 整页拼图是错的方向 | e5 里模型立即把四宫格拆回单页 | 强（设计层面） |
| 同配置复跑可以差很多 | e5d vs e5d-r2 差 32%；但 p1 三次只差 7%——方差取决于行为是否被约束 | 强 |
| 打包措辞能改变行为 | `--pack` 调用 0→1→4，复跑 3 | 中（离散、可复现，但 n=1/单元格） |
| 技能 vs 裸模型无质量差异 | e1（3 次）、e2b、p1（3 次）全部 0.850 / 1.000 | 强 |
| 三臂质量相同 | e1 / e2b / e3b 全部 0.850 / 1.000 | 强 |
| 生产版技能可用 | p1-prod 三次都是 0.850 / 1.000；每次 8 会话都在调用 `pdfx.py` | 强（3 次） |
| 生产版可重复 | 三次：76.1 / 79.0 / 81.4 秒/页，极差 1.07× | 强（同配置） |
| 生产版总耗时低约 20% | 3v3：79.0（76.1–81.4）vs 99.4（86.4–109.3）秒/页；总耗时 609–651 vs 691–874 秒，区间不重叠 | 中 |
| 逐页也更快 | 只有 5/8 页更快；胜在少数页的大幅节省（129→44、80→53），easy 页反而慢几秒 | 否（方向不一致） |
| 像素技能与尺子成本相当 | 93.3 vs 90.4 秒/页 | 弱：差 3%，任何口径下都不算差异 |
| 模型能力主导成本 | kimi 慢 6 倍、4/8 超时 | 中 |

## 四、缺口（收缩前应当知道）

1. ~~像素臂没有一次干净测量~~ **已补齐（2026-11-06）**：`e3b-pixels`，0 次联网调用，
   0 超时，0 解析问题。

3. **其余条件仍是 n=1**（尺子、像素、复审、打包、kimi）。成本结论只对 p1 vs e1 成立。
4. **样本饱和。** 要区分方法差异必须换更难的题（块面积 <1%、单页 6 个以上目标）。
